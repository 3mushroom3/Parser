# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

«База АПК» — база сельхозпроизводителей. Собирает декларации соответствия с `pub.fsa.gov.ru` (двумя путями, см. ниже) и предоставляет REST API + SPA для работы с ними: реестр, карта, избранное, папки, заметки, свои базы контактов (XLS-импорт), подписки/оплата (ЮKassa), Telegram-уведомления.

## Commands

```bash
cd backend && npm install   # установка зависимостей
node server.js              # запуск сервера (порт 3001)
node scripts/backfill-opendata.js [--limit N]  # разовый бэкафилл истории из открытых данных РДС
node scripts/smoke-declaration.js 16827658     # отладка одной декларации без HTTP-сервера
node scripts/probe-api.js 16827658             # диагностика сырых ответов FSA API
```

Тестов и линтера (в рабочем состоянии) нет.

**Перед первым запуском:** нужен `backend/.env` с `JWT_SECRET` (32+ символов, см. `.env.example`) — сервер **не стартует** без него (fail-closed, `config/jwtSecret.js`). Сгенерировать: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`. На первом запуске с пустой БД создаётся `admin` со случайным паролем — он печатается **один раз** в лог (`logger.warn`), больше нигде не сохраняется.

## Architecture

**Стек:** Node.js + Express, **SQLite через better-sqlite3** (`backend/services/db.js`, файл `data/fsa_parser.db`) — не JSON-файл.

**Два источника деклараций:**

1. **Живой API** (`services/apiClient.js` → `services/parserService.js`) — анонимный логин на pub.fsa.gov.ru → JWT (кешируется, авто-обновление при 401/403). Жёсткий лимит: страница 21+ отдаёт `RDS-APP-9995` (максимум ~2000 записей за один непрерывный диапазон дат). `parserService.js` дробит диапазон на окна (`FSA_DATE_CHUNK`) и рекурсивно бисектит окно пополам при упоре в лимит; чекпоинтит пройденные окна в `status.lastCompletedDate`, чтобы не пересканировать всё при каждом рестарте.
   **С момента появления opendata-пайплайна живой API по умолчанию сканирует только текущий месяц** (`server.js: startOfCurrentMonth()` — если `FSA_DATE_FROM` не задан явно, дефолт — 1-е число текущего месяца, `FSA_DATE_CHUNK` дефолтится в неделю). Раньше жил в режиме непрерывного бэкафилла с фиксированной исторической даты — это было избыточно, т.к. историю теперь закрывают открытые данные. Ручной бэкафилл через `FSA_DATE_FROM`+`FSA_DATE_CHUNK` по-прежнему работает как раньше (для отладки/спецслучаев).
2. **Открытые данные РДС** (`services/opendataClient.js` + `opendataParser.js` + `opendataService.js`) — `fsa.gov.ru/opendata/7736638268-rds/` отдаёt тот же реестр помесячными `.7z`-архивами (CSV внутри, без лимита пагинации). Раз в сутки (`fsaConfig.opendata.cronSchedule`, дефолт 02:15) `opendataService.runOpendataImport()` докачивает ещё не обработанные архивы, распаковывает, фильтрует по регламенту и доливает `declarations` (`INSERT OR IGNORE` по `id` — не трогает то, что уже видел живой API). Обработанные архивы трекаются в таблице `opendata_imports` (идемпотентность). История доступна примерно с января 2022; более старые архивы используют 2-3 разных легаси-формата CSV — при ошибке парсинга конкретного под-файла архива он просто пропускается (не роняет весь архив), см. `opendataService.js`.
   **Важно:** `7za` вызывается напрямую через `child_process.spawn` (не через `7zip-min` — та библиотека не вычитывает stdout ребёнка и виснет навсегда на архивах в сотни МБ).
   Разовый бэкафилл: `node scripts/backfill-opendata.js [--limit N]`.

**Frontend:** `frontend/index.html` + `frontend/css/style.css` + `frontend/js/app.js` (не один файл — три отдельных, ~1000/300/2900 строк соответственно), ванильный JS/CSS без фреймворков. Иконки в шапке — inline SVG (не эмодзи). Подвал сайта (`.site-footer`, фикс. позиция) — на логин-странице и во всех разделах приложения; там же ссылки на Пользовательское соглашение и Политику конфиденциальности (модалки `tosModal`/`privacyModal`).

## Key Config (environment variables)

Все переменные имеют дефолты в `backend/config/fsaConfig.js` (кроме JWT_SECRET — `config/jwtSecret.js`, без дефолта, fail-closed).

| Переменная | Дефолт | Назначение |
|---|---|---|
| `JWT_SECRET` | — (обязателен) | ≥32 символов, иначе сервер не стартует. `ALLOW_INSECURE_JWT_SECRET=true` — только для локальной разработки |
| `FSA_CRON_SCHEDULE` | `*/30 * * * *` | Расписание живого парсинга |
| `FSA_DATE_FROM` | 1-е число тек. месяца | Если не задан явно — живой API сканирует только текущий месяц (историю закрывают открытые данные) |
| `FSA_DATE_TO` | — (до сейчас) | Дата конца диапазона |
| `FSA_DATE_CHUNK` | `week` (неделя), если `FSA_DATE_FROM` тоже не задан | Нарезка диапазона: `week`/`biweek`/`month`/`day`/число дней. Если `FSA_DATE_FROM` задан вручную (ручной бэкафилл) — по-прежнему обязательно указывать и это |
| `FSA_FORCE_RESCAN` | `false` | `true` — игнорировать чекпоинт `lastCompletedDate`, пересканировать все окна заново |
| `FSA_PAGE_SIZE` | `100` | Записей за страницу (макс. 100) |
| `FSA_MAX_RECORDS` | `0` (без лимита) | Максимум записей в БД |
| `FSA_FETCH_CONCURRENCY` | `3` | Параллельных запросов деклараций |
| `FSA_DELAY_MS` | `1500` | Задержка между запросами списка (мс) |
| `FSA_DETAIL_DELAY_MS` | `300` | Задержка перед запросом карточки декларации — см. предупреждение про WAF ниже |
| `FSA_TECH_REG_IDS` | `32` | ID техрегламентов `filter.idTechReg` (через запятую). `32` = ТР ТС 015/2011 "О безопасности зерна" |
| `FSA_TECH_REGLAMENT` | — | Локальный фильтр-подстрока (резервный, менее точен) — общий для живого API и opendata-пайплайна |
| `FSA_OPENDATA_URL` | `fsa.gov.ru/opendata/7736638268-rds/` | Страница открытых данных РДС |
| `FSA_OPENDATA_DIR` | `data/opendata/` | Кэш скачиваемых архивов/CSV (временный, чистится после обработки) |
| `FSA_OPENDATA_CRON` | `15 2 * * *` | Расписание доливки открытых данных |
| `FSA_PROXY_URL` / `FSA_LOCAL_ADDRESS` | — | SOCKS5-прокси или конкретный локальный IP для обхода банов FSA WAF |
| `PORT` | `3001` | Порт HTTP-сервера |

## Data Schema

Таблица `declarations` в SQLite (`backend/services/db.js`) — актуальная схема там же. Ключевые поля: `id`, `fsaId`, `declNumber`, `source` (`fsa`/`manual`), `status` (`active`/`suspended`/`expired`/`archived`), `productGroup`, `technicalReglament`, `regDate`, `endDate`, `applicantName`, `lastName/firstName/middleName/shortName`, `address`, `phone`, `productName`, `batchSize`, `otherInfo`, `farmerType`, `okved`, `inn`, `productionSites` (JSON), `fsaUrl`, `fetchedAt`.

## Non-obvious Behaviours

- При 5 (10 в `parserService.js`) последовательных ошибках загрузки страницы списка — окно прерывается.
- Ошибка загрузки отдельной декларации — логируется, парсинг продолжается.
- CSV-экспорт отдаётся с UTF-8 BOM для корректного открытия в Excel.
- **Импорт Excel/CSV-баз** («Мои базы» — `userContactsParser.js`, админский импорт — `xlsImporter.js`) идёт через общий `services/sheetAnalyzer.js`: лист, строка шапки (в т.ч. многоуровневая), типы колонок определяются по заголовку и содержимому, «смешанные» ячейки (адрес + директор + телефон) разбираются, строки без названия/ИНН приклеиваются к предыдущей компании. Номера колонок нигде не захардкожены. Выполняется в worker-потоке (`workers/importWorker.js` через `services/importJobs.js`) — сверка с реестром проходит по всей `declarations`. Проверять изменения на образце `Луганская Народная Республика (Образец) (2).xlsx` (лежит локально в корне, в git не добавлен — там персональные данные).
- **FSA API хранит регламент как полное название** (`"О безопасности зерна"`), а не код (`"ТР ТС 015/2011"`). Поиск по коду не работает.
- **Текстовые фильтры `technicalReglaments` FSA API игнорирует** — фильтрация локальная через `FSA_TECH_REGLAMENT`.
- **FSA API лимит: страница 21+ → HTTP 400 `RDS-APP-9995`**. `parserService.js` дробит окно пополам при упоре в лимит и пересканирует рекурсивно — декларации сверх ~2000 на окно больше не теряются молча.
- **ФСА стоит за антифрод-WAF (Solar JSOC)** — резкий рост объёма запросов может привести к бану/троттлингу IP сервера (TCP на 443 виснет, ICMP отвечает). При этом — подождать и увеличить `FSA_DETAIL_DELAY_MS`, либо настроить `FSA_PROXY_URL`.
- Открытые данные РДС: у части архивов за 2022 год встречается 2-3 легаси-формата CSV (другой разделитель/схема колонок) — такие под-файлы пропускаются с логом ошибки, не блокируя остальные.
- Дефолтный пароль admin — случайный, печатается в лог один раз при создании аккаунта на пустой БД. Если пропустили — удалить строку `admin` из таблицы `users` и перезапустить сервер.
- Правильный формат запроса FSA API: тело POST использует `filter{}` (не `filters`), `columnsSort`, `count`.
